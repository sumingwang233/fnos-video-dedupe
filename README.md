# 视频查重助手 video-dedupe

简体中文 | [English](README.en.md)

扫描 NAS 授权目录里的视频，找出**字节完全相同**（SHA-256）与**画面高度相似**（pHash 视觉指纹）的重复文件，人工审阅后按签名计划执行**显式确认的永久删除**——删之前反复核对，删之后留档备查。

[下载](#下载) · [看看界面](#看看界面) · [三步开始](#三步开始) · [平时怎么用](#平时怎么用) · [常见问题](#数据与常见问题)

当前版本 **v3.0.2**（2026-10-14）。适用于飞牛 fnOS **1.1.3100 及以上**（统一网关）的 **x86** 机型；界面为简体中文，仅管理员账号可操作。所有依赖随包内置，安装与运行都不需要外网。

## 三步开始

1. **授权目录**：系统设置 → 应用 → 视频查重助手 → 访问权限，添加要扫描的文件夹。权限选**读写** ＝ 该目录中的重复视频可清理；选**只读** ＝ 仅作对比参考，绝不删除。
2. **扫描**：打开应用点「开始扫描」，按「查找视频 → 识别内容 → 整理结果」三个阶段推进，可随时停止（已识别的结果下次扫描直接复用）。首次会逐个读取视频画面计算指纹（大库可能需要数小时，建议停写后扫描）；之后重扫会自动跳过没有变化的文件，速度很快。自选扫描范围时，子目录绑定它所属的授权文件夹，不会误扫其他文件夹下的同名目录。
3. **审阅并生成清理清单**：逐组查看重复视频（缩略图 / 大小 / 画面指纹距离），「完全相同」分组查看建议后点「应用建议」批量勾选，「画面相似」分组进入并排比较（10%–90% 五个时间点的画面同步切换 + 分辨率 / 时长 / 编码 / 音轨 / 字幕差异高亮）逐项决定 → 生成清理清单（确认页列出全部保留 / 清理决定）→ 确认执行。**当前版本清理执行入口在系统回收站真机验证完成前暂不可用**（见常见问题）。

## 平时怎么用

| 想做的事 | 操作 |
|---|---|
| 新存了一批视频，想查重 | 概览 → 开始扫描 → 审阅 |
| 只扫某个子目录 | 概览 → 扫描范围 → 选择要扫描的子文件夹（绑定所属授权文件夹，不会扫到其他文件夹下的同名目录） |
| 同一部片子存了两份一模一样的 | 审阅页「完全相同」分组 → 查看批量建议（保留哪份、为什么）→ 点「应用建议」主动勾选 |
| 转码 / 压制产生的近似版本想留一个删一个 | 「画面相似」分组进入并排比较：五个时间点画面同步切换、参数差异高亮，逐项标记 |
| 审阅到一半想下次继续 | 选择自动保存为草稿；分页浏览、刷新或换标签页不丢，两个标签页冲突时会提示刷新而不是覆盖 |
| 查以前删过什么 | 需要报告时在概览页对已完成的扫描手动导出（CSV / HTML），保存到共享文件夹 `video-dedupe/data` |
| 增删了授权目录或改了读写权限 | 系统设置改完后，停止并启动本应用；旧扫描作废重扫（指纹缓存保留，很快） |

## 数据与常见问题

**删除安全吗？会不会误删？**
按「默认预演」设计：没有显式确认绝不删除；每个重复组至少保留一份，全选会被拒绝；只读目录与硬链接永不进入删除名单。清理计划由内容哈希签名，执行时再次核对目录配置、挂载点、文件状态与 SHA-256，任何不符整批停止；Linux 上删除先在同目录原子暂存、复核后才真正移除，每一步先写 journal，中断可恢复。**注意**：现有执行路径是**直接永久删除**（不进回收站）——正因如此，开发中的下一版计划改为移入系统回收站，在该能力通过飞牛真机验证之前，**清理执行入口保持关闭**；扫描、审阅与清理清单的生成不受影响。

**扫描或清理做到一半，刷新页面 / 重启应用会怎样？**
任务状态（扫描、生成清理清单、执行清理）持久化保存：刷新、离开页面或重启应用后，概览页和状态页仍能查到同一个任务及其结果；被重启打断的任务会如实标记为「已中断」，不会假装还在运行。审阅时已勾选的选择保存为草稿，同样不因刷新丢失。

**我的数据放在哪里？**
扫描数据库与缩略图在应用私有目录，不占用共享空间；导出的报告（CSV / HTML）保存到共享文件夹 `video-dedupe/data`，文件管理器随时可查。

**需要联网吗？要装 Python 或 Docker 吗？**
都不需要。v0.2.0 起为纯原生实现（无容器）；ffmpeg / ffprobe 与 numpy 全部随包内置，安装期零网络依赖。

**普通用户账号能操作吗？**
不能。界面经飞牛统一网关接入，沿用 NAS 账号体系鉴权，仅管理员可进入与操作——所有页面、缩略图与状态接口统一校验管理员身份，非管理员一律拒绝；开发用的 TCP 直连模式不信任客户端伪造的身份头。

**和 v0.1.x 的 Docker 版是什么关系？**
v0.1.0 曾基于 VDF 容器实现，v0.2.0 起重写为纯原生 fpk 应用。两者数据不互通，建议卸载旧版换装新版。

**支持哪些视频格式？**
常见容器与编码由内置 ffmpeg 解码（mp4 / mkv / mov / avi / wmv / flv / m2ts 等）；损坏或无法读取的文件降级记录为警告，不会中断扫描。

__开发与项目结构__

Windows + WSL Ubuntu 双平台开发；Python 3.12 标准库为主（除 numpy 外零第三方 import），unittest 双平台全绿才可提交：

```sh
py -3.12 -X utf8 -m unittest discover -s tests -v        # Windows 测试
py -3.12 -X utf8 build_fpk.py                            # 构建 fpk（fnpack 1.2.3）
VD_ALLOW_NO_ADMIN=1 py -3.12 -X utf8 webui.py --config config.local.json --tcp 18099  # 本地 UI 冒烟
```

架构一句话：`videodedupe.py`（扫描 / 指纹 / 分组 / 计划 / 删除引擎）＋ `webui.py`（stdlib http.server 界面，AF_UNIX socket 接统一网关，样式与脚本在 `static/`）＋ `tasks.py`（任务状态与互斥锁，复用扫描数据库）＋ `fpk/`（fnOS 应用骨架与生命周期脚本）＋ `build_fpk.py`（打包）。开发纪律与模块边界见 [AGENTS.md](AGENTS.md)，验证记录见 [VALIDATION.md](VALIDATION.md)。
