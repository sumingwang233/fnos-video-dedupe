# 视频查重助手：面向普通用户的流程与代码重构方案

## 一、结论与已确定的方向

当前项目已经具备可用的扫描引擎和较完整的删除保护，但产品流程仍然围绕内部实现展开：用户需要理解“审阅、生成计划、预演、确认执行”，而真正需要的信息——**两个版本有什么不同、应该保留哪个、操作完成了没有、能否恢复**——没有得到充分呈现。

本轮应优先重构选择逻辑、任务状态和清理语义，再调整页面结构。现有 SHA-256、pHash、授权目录校验和文件身份保护继续复用，不重写整个引擎。

已经确认的产品边界：

- 核心目标：帮助用户保留满意的视频版本，再清理副本。
- 重塑完整使用流程，保留现有 Strata 浅色/深色视觉风格。
- SHA-256 完全相同的文件允许用户主动批量选择；视觉相似文件逐组判断。
- 使用多帧画面和参数并排比较，本轮不做视频播放器。
- 清理必须进入飞牛系统回收站；恢复和手动清空在系统文件管理器完成。
- 接受一次官方授权；不借用开发机登录状态，不回退到永久删除或应用自建隔离目录。
- 管理员单工作区，主要验收规模约一万视频。

**审查依据**：当前 `e91295f` / v0.2.27 的源码、测试、生命周期脚本、历史记录和仓库内界面截图。本轮未运行测试、构建或真机操作；以下区分源码可确认的问题与需要平台验证的条件。

## 三、重塑后的使用流程

**主流程：选择文件夹 → 扫描 → 比较并选择保留版本 → 确认清理 → 查看结果。**

“签名计划、预演、journal”继续存在于内部，不再作为用户必须理解的独立阶段。

### 1. 首页与扫描范围

- 首页围绕当前状态呈现一个主操作：首次“选择文件夹并扫描”、扫描中“查看进度”、扫描后“继续整理”。
- 扫描范围明确区分“全部已授权文件夹”和“自选文件夹”；自选模式未选择时禁止启动，不能悄悄变成全盘扫描。
- 文件夹同时展示名称、完整位置和权限：“可清理”或“仅参与比较”。
- 保留系统授权入口说明；授权变化仍要求重启应用，不伪装成即时刷新。
- 已有审阅草稿时重新扫描，说明旧草稿的归属；不自动把旧选择套到新结果。

### 2. 扫描过程

- 显示“查找视频、识别内容、整理结果”三个阶段。
- 总数尚不明确时显示已发现数量，不显示伪造的百分比或预计剩余时间。
- “停止扫描”在目录遍历、文件处理和分组循环中均可响应；已经成功计算的缓存保留。
- 停止后明确写“再次扫描会复用已有识别结果”，不称为已经实现精确断点续跑。
- 结束区分：完成、完成但有跳过、已停止、失败；提供数量、原因和可执行的下一步。

### 3. 扫描结果与比较

- 分开呈现“完全相同”和“画面相似，待比较”，不把两者统一宣传为已确认的重复。
- 默认先显示完全相同结果；支持类型、待处理/已处理、文件夹、名称筛选。
- 每页 20 组，按服务端分页；缩略图延迟加载，超大分组也不一次加载全部成员。
- 每个文件明确标注“保留”“待清理”“受保护”；点击画面用于比较，不兼任删除勾选。
- 保留多份、整组跳过都是正常决定，不要求每组必须产生清理项。

完全相同文件的批量辅助：

- 用户先查看建议，再主动点击“应用建议”；初次进入页面不自动选中清理项。
- 优先保留已有受保护副本；没有受保护副本时，以文件夹路径和文件名的稳定顺序提出建议，并展示理由。
- 不使用文件大小推断质量。
- 有外挂字幕差异、读取异常等需要人工判断的组，跳过批量处理并列出原因。
- 混合相似组中的完全重复副本仍按各自 SHA 子组处理，不能顺带选择其他转码版本。

视觉相似组：

- 默认所有文件保留，用户逐项标记待清理版本。
- 同步切换 10%、25%、50%、75%、90% 五个相对时间位置，并显示各自实际时间。
- 并排展示分辨率、时长、编码、帧率、大小，以及音轨语言、声道、内嵌/外挂字幕差异。
- 高亮差异，不将分辨率、码率或 pHash 距离包装成“质量评分”或相似百分比。
- 每个待清理文件必须有一个仍被保留的直接匹配对象；存在差异时，在该组内明确确认。
- 不支持判断的组允许跳过，并在提交前说明原因。

### 4. 清理确认

用户点击“查看清理清单”后，后台生成并核验计划；完成后直接进入同一流程的确认页。

确认页展示：

- 本次移入回收站的文件数量和合计文件大小。
- 各组保留哪些文件、清理哪些文件及所在文件夹。
- 尚需注意的音轨、字幕、时长差异。
- 系统回收站归属及恢复入口说明。
- 返回修改入口，返回后保留全部选择。

最终按钮使用“确认移入系统回收站”。内部仍绑定不可变计划及其确认值，不要求普通用户输入哈希，也不依赖额外的浏览器 `confirm()` 弹窗承载主要信息。

### 5. 完成与清理记录

- 展示已移入、未处理、失败和状态待核实的数量。
- 移入回收站后显示“已移入回收站的文件大小”，不能显示为“已释放空间”。
- 不提供应用内自动清空或定期清空功能。
- 用户通过系统文件管理器恢复；没有经过验证的直达链接时，提供准确的操作路径。
- 页面刷新、离开和应用重启后，清理记录仍然可查。
- 对已经在系统中恢复或清空的文件，不擅自推断最新状态；未经查询的记录只表示当时操作结果。

## 四、具体代码与数据改造

### A. 系统回收站：先验证能力，再接入

这是本轮的硬前置条件。现有技能资料包含 `file.rm` 和回收站接口，但不足以证明 `file.rm` 一定进入回收站，更不能证明它与原执行器具有等价的文件身份保护。

先用独立测试目录验证：

1. fnOS 1.2.0800 上可供第三方应用使用的接口与官方授权方式。
2. 个人目录、共享目录等受支持位置的回收站行为。
3. 回收站关闭、不支持或权限不足时，操作必须拒绝，不能永久删除。
4. 文件进入哪个账号的回收站，能否按原文件名、原位置恢复。
5. 能否可靠关联一次请求与回收站结果，处理超时、断连和重试。
6. 接口是否能绑定已核验的文件身份，或提供等价的安全操作方式。

**通过条件**：既满足系统可恢复性，也保留当前的文件替换防护。只有“按路径调用删除接口”不足以通过；不能先改成临时名称，再让用户恢复出 `.vd-delete-*` 文件。

验证通过后，仅新增一个具体的平台适配模块，负责授权、能力检查、移入回收站和结果核实。不设计多后端插件体系，不打包开发机 trim-cli 会话或凭据。

验证不通过时：

- 扫描、比较、草稿和清单功能继续可用。
- 清理入口显示不可用及具体原因。
- 不宣称本轮已完成可恢复清理，也不启用替代删除路径。

### B. 统一任务状态，消除页面各自推测

新增轻量任务协调模块，复用现有 SQLite：

- 持久化任务 ID、类型、状态、阶段、时间、进度、关联扫描/计划、完整结果及错误。
- 状态明确区分运行、请求停止、成功、部分完成、失败、中断、待核实。
- 首页、顶栏、状态页和结果页读取同一个任务记录。
- 一个工作区只运行一个有状态后台操作；扫描、比较图生成、计划核验和清理共用协调入口，不引入任务队列服务。
- 配置和参数验证完成后才占用任务；检查与占用必须原子完成。
- 核心入口继续使用跨进程操作锁，覆盖 Web 与 CLI；不能只靠进程内布尔值。
- 重启后核对未完成任务：扫描/核验标记中断；清理结合 journal 核实，绝不自动重放不确定操作。

请求行为统一：

| 接口职责                                 | 行为                                               |
| ---------------------------------------- | -------------------------------------------------- |
| 启动扫描、生成比较图、核验清单、执行清理 | POST；重复提交返回同一任务或明确忙碌状态           |
| 浏览器表单提交成功                       | 303 跳转到带任务 ID 的 GET 页面                    |
| 状态读取                                 | 返回固定任务的持久化状态，不通过“当前全局变量”猜测 |
| 结果读取                                 | 必须存在对应结果；不存在时显示处理中、中断或不存在 |
| 停止任务                                 | POST，绑定具体任务 ID，不能取消其他任务            |

移除 GET `/apply` 触发核验工作的行为；GET 只读取现有结果。

### C. 扫描范围、缓存与匹配逻辑

- 扫描范围改为明确的模式和 `{root_id, rel}` 列表。拒绝绝对路径、`..`、越界和符号链接；同一根下父子选择去重。
- 结果保存本次实际扫描范围，后续页面不再从当前配置推断历史范围。
- 将扫描和计划共用的匹配规则抽成纯函数；保持当前候选容差与 pHash 阈值，先修一致性，不凭感觉调算法参数。
- 保存完全重复子组；相似分组作为候选集合。计划中记录待清理文件对应的保留对象及直接匹配依据。
- 元数据、SHA、pHash、预览图分别保存状态，缩略图失败不能抹掉其他成功结果。
- 缓存增加算法/格式版本；重扫重试失败能力，成功且版本一致的部分继续复用。
- 单个文件消失或变化时记录跳过；授权边界、配置身份或挂载异常仍立即停止。
- 多帧预览按需生成、私有缓存、单路串行，不在首次扫描时为一万文件全部生成五张大图。
- 先保留时长窗口内的现有比较方式，补充取消和进度；不在缺少测量依据时引入向量数据库或复杂索引。

### D. 审阅草稿和清单契约

新增服务端草稿，绑定扫描 ID：

- 保存每组保留/待清理选择、跳过状态和已确认的差异。
- 更新带草稿修订号；两个标签页冲突时提示重新加载，不能静默覆盖。
- 保存失败时保留当前页面选择并禁止继续提交，直到成功保存。
- 新扫描、配置变化和文件变化不自动继承旧选择。
- 草稿可修改；已生成的执行计划不可修改。修改草稿后重新生成计划。

计划升级为新版本：

- 明确动作是 `system_trash`，绑定扫描、配置、草稿修订、平台身份及文件快照。
- 保留完整性哈希、至少保留一份、reference/硬链接保护、挂载及文件身份检查。
- 旧版永久删除计划保留为历史记录，但在新版本中禁止执行，不能直接转换成回收站计划。
- 执行前仍核验文件内容和保留对象；平台适配不能成为绕过终检的通道。
- 每项操作先记 journal，再调用平台；成功、失败、未知结果分别落盘。
- 断连后只有确认未执行的项才能重试；已完成项跳过，无法核实的项停止并提示处理。

### E. 页面代码与访问边界

保持标准库 HTTP 服务和原生 JavaScript：

- `webui.py` 保留路由、请求处理和 HTML 组装；CSS、浏览器脚本移出巨型页面字符串，作为本地静态资源随包分发。
- 不引入前端框架、模板引擎、ORM 或通用工作流框架。
- 所有业务 GET、HEAD、POST 及缩略图读取统一校验管理员；静态字体和样式可公开读取。
- 仅在统一网关 socket 模式信任注入的身份头；TCP 开发模式不得因客户端伪造头获得管理员权限。
- POST 加入 CSRF 校验、请求体大小限制和明确的参数错误响应。
- 缩略图读取验证扫描归属、当前授权和允许的文件标识，不能接受任意路径。
- 保持网关前缀，新增资源和接口均通过同一前缀生成方式引用。
- 使用原生按钮、复选框和清晰标签；键盘、焦点、窄屏和减少动画设置均保留。

### F. 导出、生命周期与兼容

- 报告导出改为独立操作；报告失败不改变扫描或清理的业务结果。
- 导出真实 NAS 位置、正确单位和空值；修复 HTML 属性错误，文本字段安全转义。
- 私有 journal 保留在应用数据目录；向共享目录导出的用户清单与 journal 区分，不再宣称私有日志自动出现在共享目录。
- 配置派生失败停止启动；空授权仍作为正常引导状态。
- SQLite 使用事务和明确版本迁移；保留原扫描、缓存和 journal。旧扫描缺少新比较信息时要求重扫，不伪造证据。
- 更新打包脚本的明确文件清单，确保新模块和静态资源进入离线包。
- 包版本继续以 manifest 为来源，消除运行时显示版本的手工漂移。
- 每个阶段追加 `Log.md`；平台验证写入 `VALIDATION.md`；同步中英文 README 和项目约束。

## 五、实施顺序与验收

| 阶段            | 交付内容                                                  | 完成条件                                               |
| --------------- | --------------------------------------------------------- | ------------------------------------------------------ |
| 0：平台能力验证 | 回收站接口、授权、恢复语义和安全契约的验证记录            | 明确支持范围；任一关键条件失败则关闭清理接入           |
| 1：基础正确性   | 范围绑定、取消提交、PRG、读取鉴权、结果类型及启动配置处理 | 不误扫、不重复提交、不假报成功、不沿用失效配置         |
| 2：任务状态     | 持久化任务、统一互斥、重启恢复、统一状态接口              | 刷新、离开和重启不丢任务身份，不出现永久假运行         |
| 3：扫描与审阅   | 匹配规则统一、异常降级、分页、草稿、明确选择语义          | 一万视频结果可分批浏览，选择可靠保存，相似组无默认清理 |
| 4：版本比较     | 按需多帧、音轨字幕差异、完全重复批量建议                  | 用户能看到保留依据；辅助选择仅在主动应用后生效         |
| 5：可恢复清理   | 新版计划、系统回收站适配、journal 核实和清理记录          | 测试文件可从系统恢复，重试不误操作，不存在永久删除回退 |
| 6：交付收尾     | 文档、迁移说明、打包和完整验收记录                        | 用户流程、代码契约、发布说明一致                       |

各阶段按架构边界拆分提交；文件安全执行器与页面调整分开评审。遵守仓库 CRG 的改前定位、改后更新及提交前影响分析流程。

后续测试与验收重点：

- **范围与提交**：两个根存在同名子目录；自选为空；取消确认；双击提交；刷新 POST 后页面；浏览器返回。
- **选择与分组**：原版与小体积转码、多个音轨/字幕版本、受保护副本、硬链接、A≈B≈C 但 A 不≈C、混合完全重复子组、全选清理被拒。
- **草稿与任务**：刷新后恢复、跨页选择、多标签页冲突、任务互斥、重启中断、清理完成但页面未收到响应。
- **扫描降级**：文件扫描中消失、损坏视频、只有缩略图失败、缓存版本变化、导出目录不可写；业务结果保持准确。
- **访问控制**：非管理员访问结果、缩略图和状态均被拒；伪造 TCP 身份头无效；CSRF 和越界输入被拒；网关前缀完整。
- **回收站**：关闭、不支持、权限撤销、授权过期、网络超时、成功响应丢失、同名新文件、原路径替换；保留项始终存在，恢复后文件名和内容正确。
- **规模与交互**：约一万文件，页面不全量加载结果和图片；遍历与分组都有进度和停止响应；真实点击路径通过，不使用 `form.submit()` 绕过事件。
- **平台与交付**：Windows 验证开发路径，Linux 验证文件安全及新执行路径；涉及打包时检查离线安装和静态资源。回收站保证必须由 fnOS 真机样本验证，不能由 mock 测试代替。

本轮已完成的是静态审查与方案制定。以上测试、真机样本写入和打包属于后续实施验收，需按项目要求明确授权后执行；在结果可恢复性得到验证之前，不开放清理功能。
