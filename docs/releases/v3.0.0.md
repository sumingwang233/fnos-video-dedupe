# 视频查重助手 v3.0.0

## 简体中文

本版本依据一次完整的代码审查（2026-10-12，19 个实施阶段）对审阅与清理流程做整体重构：审阅不再默认勾选任何删除项、画面相似组新增五帧并排比较、任务状态持久化、扫描范围绑定授权文件夹。**清理执行入口在本版本暂时禁用**（见下方状态声明）。

**状态声明：本版本起 Web 界面的删除执行入口显示「待平台验证，暂不可用」。** 下一目标是接入飞牛系统回收站（可恢复删除）；在真机验证回收站接口满足安全契约（防文件替换、可按原位原名恢复、失败即拒绝而非永久删除）之前，不开放任何删除路径，也不提供「永久删除」替代按钮。扫描、比较、审阅、计划清单、报告导出等全部功能正常。CLI 保留原有带全套安全校验的执行路径不变。

### 主要变化与修复

- 审阅不再默认预选删除项：「最小文件=建议保留」规则移除；「完全相同」组的批量建议需主动点击「应用建议」才生效——优先保留受保护副本（只读目录 / 硬链接），其余按文件夹路径与文件名稳定排序并展示理由，不使用文件大小推断质量。
- 画面相似组并排比较页：分辨率、时长、编码、帧率、大小、音轨语言、声道、内嵌 / 外挂字幕九项差异高亮；10% / 25% / 50% / 75% / 90% 五个时间点的帧画面同步切换并标注实际时间。
- 审阅页服务端分页（每页 20 组）与类型 / 处理状态 / 文件夹 / 名称筛选；选择自动保存为服务端草稿，多标签页冲突时提示刷新而不是静默覆盖。
- 扫描范围绑定授权文件夹身份：勾选某个子目录不会再误扫其他授权根下的同名目录；实际生效范围随扫描结果记录并在概览展示。
- 任务状态持久化：刷新 / 重启后扫描、计划、删除的状态与结果可查（中断如实标记，绝不自动重放不确定操作）；停止扫描在查找、识别、整理三个阶段均可响应，已识别结果复用。
- 访问边界收紧：所有页面、接口与缩略图要求管理员，POST 加 CSRF 校验，TCP 开发模式不信任伪造身份头；表单提交统一 303 跳转，不再整页 reload 重提。
- 计划确认页直接列出每组保留 / 清理文件、所在文件夹与差异注意点；返回修改保留全部选择。
- 报告导出改为显式操作（扫描成功不受导出成败影响），导出真实 NAS 路径与正确的单位换算。
- 分组呈现更诚实：SHA 完全相同（字节一致）与「画面相似 · 待确认」分开呈现；相似组的传递连通关系不再当作已确认的重复，完全重复的批量建议只作用于字节一致的副本。
- 全新应用图标：蓝色载体上双帧错位叠放、共享一枚负空间播放三角，呼应「多份副本、同一内容」的查重语义；页头符号与浏览器 favicon 同步更换。

### 升级与数据保留

在应用中心直接安装本 fpk 覆盖升级。扫描数据库自动迁移（新增范围 / 子组 / 摘要列与草稿表，旧扫描记录保留）；指纹缓存引入版本号，升级后首轮扫描会重算一次；旧扫描的审阅选择不自动继承到新扫描（草稿按扫描隔离）。**注意：升级后 Web 端删除执行入口不可用，属预期行为**（见状态声明）。逐版变更见 [Log.md](https://github.com/sumingwang233/fnos-video-dedupe/blob/main/Log.md)。

## English

This version reworks the review and cleanup workflow per a full code review (2026-10-12, 19 implementation stages): the review page no longer pre-selects any deletion candidate, similar groups get a five-frame side-by-side comparison, task state is persisted, and the scan scope is bound to its authorized folder. **The execution entry is temporarily disabled in this release** (see the status note below).

**Status note: starting with this version the web execution entry reads "pending platform verification, unavailable".** The next goal is integration with the fnOS system recycle bin (recoverable deletion); until the bin's interface passes on-device verification against the safety contract (replacement-proof, restorable to the original name and location, refuses rather than permanently deleting on failure), no deletion path is opened and no "permanent delete" fallback button is offered. Scanning, comparison, review, plan listing and report export all work normally. The CLI keeps its original execution path with the full set of safety checks unchanged.

### Highlights and fixes

- No pre-selected deletion items on the review page: the "smallest file = suggested keeper" rule is gone; the batch suggestion for byte-identical groups only applies when you click "Apply suggestion" — protected copies (read-only folders / hard links) are kept first, the rest ordered stably by folder path and filename with the reason shown; file size is never used to infer quality.
- Side-by-side comparison page for visually similar groups: nine fields (resolution, duration, codec, framerate, size, audio languages, channels, embedded / external subtitles) with differences highlighted; frames at 10% / 25% / 50% / 75% / 90% switch in sync with their actual timestamps shown.
- Server-side pagination on the review page (20 groups per page) with type / handled-state / folder / name filters; selections autosave as a server-side draft, and conflicting tabs are told to reload instead of silently overwriting.
- Scan scope bound to its authorized folder identity: selecting one subfolder no longer sweeps same-named folders under other authorized roots; the effective scope is recorded with the scan and shown on the overview.
- Persisted task state: scan / plan / deletion status and results survive refresh and restart (interruptions marked honestly, uncertain operations never replayed); stopping a scan responds during discovery, fingerprinting and grouping, and finished fingerprints are reused.
- Tighter access boundaries: admin required for every page, endpoint and thumbnail; CSRF checks on POST; forged identity headers ignored in TCP dev mode; form submissions use 303 redirects instead of full-page reloads.
- The plan confirmation page lists every keep / clean decision per group with folders and difference notes; going back preserves all selections.
- Report export becomes an explicit operation (a failed export no longer fails the scan) with real NAS paths and correct unit conversion.
- More honest grouping: byte-identical (SHA) and "visually similar · needs confirmation" are presented separately; transitive similarity chains are no longer treated as confirmed duplicates, and batch suggestions for identical groups only affect byte-identical copies.
- Brand-new app icon: two overlapping frames sharing a single negative-space play triangle on a blue carrier, echoing the "many copies, one content" dedup semantics; the header mark and browser favicon match.

### Upgrade and data preservation

Install this fpk over the previous version in the App Center. The scan database migrates automatically (new scope / subgroup / summary columns and a drafts table; existing scan records preserved); the fingerprint cache is versioned and will recompute once on the first scan after upgrading; review selections from old scans are not inherited (drafts are scoped per scan). **Note: after upgrading, the web execution entry being unavailable is expected behavior** (see the status note). Per-version changes are in [Log.md](https://github.com/sumingwang233/fnos-video-dedupe/blob/main/Log.md).
