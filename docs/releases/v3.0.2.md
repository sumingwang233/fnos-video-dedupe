# 视频查重助手 v3.0.2

## 简体中文

（版本说明：v3.0.1 仅存在于开发过程、从未公开发布，其全部内容并入本版。）

本版本包含两部分：真机验收反馈的三项体验修复（扫描实时可见、母文件夹勾选、旧审阅记录不再因新增授权失效），以及一轮安全加固审查落地的六项一致性修复（草稿竞态、任务状态、异常收尾、不确定删除结果的保守定级等）。**清理执行入口保持禁用，且封口从 Web 按钮升级为引擎层唯一门禁——CLI 与任何内部调用同样无法触达真实删除路径**（见状态声明）。

**状态声明：真实清理在引擎层封口。** `require_cleanup_available()` 是唯一门禁：`apply --execute` 在占用任务之前即被拒绝（不留任务行），真实执行体 `_apply` 开头再次拦截；预演（默认行为）不受影响。将来接入经真机验证的飞牛系统回收站执行器时才会放行，且放行的是新执行器、不是旧的永久删除路径。扫描、比较、审阅、计划清单、报告导出全部正常。**v3.0.0 发布文本中「CLI 保留执行路径」的说法自本版本起不再成立**——CLI 同样被引擎门禁拒绝。

### 主要变化与修复

**真机验收反馈修复：**

- 扫描进行中，概览四卡实时显示「完全重复候选（初步）」「候选文件合计大小」与已发现视频数（数字为已识别部分的统计，扫描结束后可能调整）；审阅页在扫描期间即可进入——实时只读预览已发现的字节完全重复组与初步建议（受保护副本优先保留），刷新查看最新，画面相似组仍待扫描完成。
- 扫描范围可直接勾选母文件夹：每张授权卡片新增「扫描整个文件夹（含所有子目录）」，不再需要点开逐个勾选子目录；勾选整根后该根的子目录勾选自动并入。
- 新增授权文件夹不再导致旧扫描的审阅记录失效：目录身份校验从全量比对改为逐根比对——扫描时的每个授权根仍存在且挂载一致即可查看；移除或替换了扫描时的目录才要求重新扫描。

**安全加固（2026-10-13 审查，六项）：**

- 差异确认随选择变化失效：勾选任何实际变化都会使该组的「已确认差异」回到待确认状态并重新给出确认入口；确认保存的是确认时刻的选择快照，新勾选的文件不会继承旧确认。
- 审阅草稿保存改为串行队列 + 编辑序号：慢响应、连续编辑、多标签页场景下不再出现「页面显示已保存但实际未保存」；修订号冲突（409）时停止自动覆盖并提示刷新；生成清理计划前会等待全部修改保存完成，且计划只使用提交时修订号对应的草稿快照——服务器端修订不符即拒绝。
- 计划状态页以数据库任务行为唯一事实来源：查询指定任务绝不显示其他任务的进度；任务失败 / 中断 / 结果损坏时如实展示，不再回退读取旧的全局状态文件；任务占用后、后台线程接管前的任何异常都会把任务记为失败，不悬挂「运行中」。
- 删除执行结果不确定时保守定级：日志不可读或存在未完成条目 → 标记「待人工核实」，绝不当作普通失败自动重试；执行器异常、进程中断、重启核对等所有入口采用同一定级规则。
- 比较页拆分「存在差异」与「需额外确认」：分辨率 / 编码等展示差异与需要额外确认的判定分开；元数据读取失败的成员显示「无法完整比较」，不再被误判为参数一致；超大分组存在未展示的待清理成员时禁用整组一次确认并说明原因。
- 预览帧生成改为显式操作：查看只读缓存，缺缓存时点击生成（跨进程操作锁防并发、锁内复查缓存、忙碌时明确提示）；扫描中的实时指标措辞改为候选口径，不再出现「可释放空间」式的承诺性数字。

## English

(Version note: v3.0.1 existed only in development and was never published; all of it is folded into this release.)

This release carries two parts: three usability fixes from real-hardware acceptance feedback (live scan metrics, whole-folder scope selection, review history surviving new authorizations) and six consistency fixes from a safety review (draft races, task state, exception cleanup, conservative classification of uncertain deletion outcomes). **The execution entry stays disabled — and the seal moves from the web button to the engine as the single gate: the CLI and any internal caller can no longer reach the real deletion path either** (see the status note).

**Status note: real cleanup is sealed at the engine layer.** `require_cleanup_available()` is the single gate: `apply --execute` is rejected before a task is even claimed, and the real executor `_apply` re-checks at its head; dry-runs (the default) are unaffected. It will only be opened for a new recycle-bin executor after on-device verification — never for the old permanent-delete path. Scanning, comparison, review, plan listing and report export all work normally. **The v3.0.0 note that "the CLI keeps its execution path" no longer holds from this version on** — the engine gate rejects the CLI too.

### Highlights and fixes

**Acceptance-feedback fixes:**

- Live scan metrics: while a scan runs, the overview cards show preliminary exact-duplicate candidates, their combined size and the number of videos found (statistics over the identified portion, may adjust when the scan finishes); the review page is reachable during a scan as a live read-only preview of exact-duplicate groups found so far with preliminary suggestions (protected copies kept first) — refresh for the latest, visually similar groups still wait for completion.
- Whole-folder scope selection: each authorized-folder card gains a "scan the entire folder (all subfolders)" checkbox, so scanning one parent folder no longer means ticking every subfolder; sub-selections of a root are folded into it when the root is selected.
- Adding an authorized folder no longer invalidates review history from earlier scans: identity checks switched from whole-config comparison to per-root comparison — as long as every root involved in a scan still exists with the same mount identity it stays viewable; only removing or replacing a scanned folder requires a rescan.

**Safety hardening (2026-10-13 review, six items):**

- Difference confirmations invalidate on any real selection change: the group drops back to "needs confirmation" with the confirm entry re-shown; a confirmation stores the snapshot of selections at the moment it was given, so newly ticked files never inherit an old confirmation.
- Draft saving becomes a serial queue with edit sequence numbers: slow responses, rapid edits and multiple tabs can no longer produce "shown as saved but actually not"; on a revision conflict (409) automatic overwriting stops and the page asks to reload; generating a plan waits for all edits to be saved and uses exactly the draft snapshot of the submitted revision — the server rejects a mismatched revision.
- The plan status page treats the database task row as the single source of truth: querying one task never shows another task's progress; failed / interrupted / unreadable results are shown honestly with no fallback to the stale global state file; any exception between claiming a task and the worker thread taking over records the task as failed instead of hanging in "running".
- Uncertain deletion outcomes are conservatively classified: an unreadable journal or pending entries become "needs manual verification" and are never auto-retried as an ordinary failure; the executor's exception path, process interruption and restart reconciliation all share one rule.
- The comparison page separates "has differences" from "needs extra confirmation": displayed differences and the confirmation requirement are decided independently; members whose metadata failed to read show "cannot fully compare" instead of being judged identical; a large group with unshown selected members disables the one-shot group confirmation with the reason stated.
- Preview-frame generation becomes an explicit operation: viewing is cache-read-only, missing caches are generated on click (cross-process operation lock against concurrency, cache re-checked under the lock, explicit busy response); live scan metrics use candidate wording with no "reclaimable space"-style promise.

### Upgrade and data preservation

Install this fpk over the previous version in the App Center. No database migration is needed; scan records, drafts and the fingerprint cache are all preserved. After upgrading, the execution entry (web and CLI) being rejected by the engine is expected behavior (see the status note). Per-version changes are in [Log.md](https://github.com/sumingwang233/fnos-video-dedupe/blob/main/Log.md).
